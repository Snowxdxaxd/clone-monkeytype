# Клавиши

**▶ Live demo:** https://demo-monkeytype.onrender.com/ (free-инстанс Render: первый запрос будит сервис ~30–60 сек)


Клон Monkeytype — тренажёр печати с мультиплеером: тесты на время и на слова, два языка, таблица лидеров с серверной проверкой результатов и гонки по коду комнаты.

## Запуск

Требуется Node 24+. Сборка не нужна.

```
npm install
npm start          # порт 3020, слушает 0.0.0.0
```

Порт переопределяется переменной `PORT`. Данные лежат в `data/app.db` (SQLite, папка в .gitignore).

## Режимы

- Тест на время: 15 / 30 / 60 / 120 секунд, слова неограничены.
- Тест на слова: 10 / 25 / 50 слов.
- Язык: русский или английский (списки по 300 частых слов в `public/js/words.js`, используются и браузером, и сервером).

Управление: печать — любые символьные клавиши, Backspace — исправление (в пределах текущего слова; в предыдущее слово можно вернуться, только если в нём есть ошибка или лишние символы), Tab — начать заново.

Лента слов показывает три строки, активная строка держится в середине; непройденное — серым, верное — белым, неверное — красным, лишние символы — красные с подчёркиванием. Каретка — мигающая палка перед текущим символом.

## Метрики

- WPM = верные символы (включая пробелы завершённых слов) / 5 / минуты.
- Raw WPM = все введённые символы (верные + неверные + лишние) / 5 / минуты.
- Точность = верные / (верные + неверные + лишние) * 100.

Каждую секунду теста записывается сэмпл `{t, wpm, raw}`; по ним рисуется график результата (canvas, две линии + подписи осей).

## Античит

Результат приходит в `POST /api/results`; сервер сохраняет его в любом случае, но помечает `validated=0`, если не прошла хотя бы одна проверка. В лидерборд попадают только записи с `validated=1`.

Проверки:

1. Режим и конфигурация существуют (`time`: 15/30/60/120, `words`: 10/25/50).
2. Окно времени: для `time` — `elapsedMs` равен `config * 1000` с допуском ±2000 мс; для `words` — от 3000 до 600000 мс.
3. Границы: `wpm ≤ 240`, `accuracy ≤ 100`.
4. Сходимость с сэмплами: последнее сэмпл-значение `wpm` должно совпадать с заявленным с допуском 3.
5. Сходимость с символами: `chars.correct / 5 / (elapsedMs / 60000)` должно совпадать с заявленным `wpm` с допуском 5.

Схема таблицы: `results(id, name, mode, config, wpm, raw_wpm, accuracy, chars_json, samples_json, elapsed_ms, validated, race, created)`.

`GET /api/leaderboard?mode=time&config=30` возвращает топ-20 валидных записей по убыванию wpm.

Имя игрока берётся из сессии (`POST /api/login` по имени, cookie на 30 дней); поле имени — в шапке страницы. Результаты, отправленные без сессии, сохраняются как «Гость».

## Гонки

WebSocket `/ws`, комнаты в памяти. Код комнаты — 6 символов A-Z0-9. Сообщения:

- `race:create {name, lang}` → `race:created {code}`;
- `race:join {code, name, lang}` → `race:joined` + `race:lobby {state, players}`;
- `race:start` (любой участник в ожидании) → отсчёт `race:countdown {n}` 3-2-1 → `race:started {words, startTime}` с 50 случайными словами выбранного языка;
- `race:progress {chars, wpm, accuracy}` — клиент шлёт каждые 500 мс, сервер рассылает всем не чаще раза в 100 мс (`race:progress {players}`);
- `race:finish {wpm, accuracy, chars}` — фиксация финиша; когда завершили все (или через 180 секунд) → `race:finished {results}`, отсортированы по прогрессу, затем по wpm.

После гонки клиент отправляет свой результат в `POST /api/results` с кодом комнаты; проверка та же, что для обычных результатов, окно времени — по правилам режима слов. Гонка проверяется тем же античитом, поэтому «дорисовать» себе 400 wpm через WS не получится — в лидерборде такая запись не окажется.

Ссылка вида `/?race=КОД` автоматически открывает вкладку гонки и присоединяет к комнате.

## Структура

```
server.js               — API, античит, сид, WS-комнаты
lib/                    — каркас (http, db, ws, auth, util)
public/index.html       — страница
public/css/style.css    — тёмная тема, моноширинный системный стек
public/js/app.js        — движок печати, график, лидерборд, гонки
public/js/words.js      — списки слов (ru/en, по 300)
scripts/ws-smoke.mjs    — дымовой тест гонок: node scripts/ws-smoke.mjs
```

## Сид

При пустой базе в `results` добавляются 6 записей: Мира (78), Даша (71), Артём (65), Лёша (52), Гость (44) — валидные, и «Читер» с 400 wpm — заведомо невалидная (в лидерборд не попадает, видно только в БД).

## Ограничения

- Комнаты гонок живут в памяти и исчезают при перезапуске сервера; завершённые комнаты чистятся через 10 минут (осознанное ограничение: для портфолио персистентность комнат не нужна).
- Авторизация демо-режима «по имени»: тот, кто знает имя, может войти под ним.
- Античит проверяет согласованность метрик, но не может отличить автокликер с правдоподобной кривой скорости от живого человека.
